# MAHSUD Dataset Provenance

## Current file in use

| Field | Value |
| --- | --- |
| File | `data/sample/kpk_incidents_demo.csv` |
| Type | **SYNTHETIC demonstration data — NOT real incidents** |
| Generated by | `src/data_collection.py::generate_demo_dataset` (seed = 42) |
| Rows | ~8,800 after cleaning (8,839 raw incl. intentional duplicates) |
| Date range | 2002-01 through 2024-12 |
| Geography | Khyber Pakhtunkhwa district names (real place names, synthetic events) |

\* year/month are derived during cleaning; raw CSV omits them.

## Why demonstration data?

This project was built in an offline environment. Verified incident-level datasets
(PIPS, SATP, GTD) require manual extraction, registration, or have terms of use that
must be reviewed. **No real incidents, casualties, dates, or source citations were
invented.** The demonstration data exists only so the software pipeline can be
developed, tested, and demonstrated.

Every synthetic row carries `verification_status = "demonstration_synthetic"` and
`source_name = "MAHSUD synthetic demonstration dataset (NOT real incidents)"`.

The yearly *shape* (rise to a 2012–2014 plateau, decline after 2014, partial
resurgence 2022–2024) loosely follows the well-documented public trend curve for
Pakistan conflict data, but **magnitudes are arbitrary** and must never be cited.

## Intentional flaws (for testing the cleaning pipeline)

- ~30 duplicate rows (identical content, new IDs)
- ~5 rows with missing/invalid dates (dropped by cleaning)
- ~8% missing values in fatalities/injuries (**kept as missing, never treated as zero**)

## How to replace with verified data

1. Choose a documented source (see `src/data_collection.py::PUBLIC_SOURCES`):
   - PIPS annual Pakistan Security Reports (https://www.ips.org.pk/)
   - SATP incident listings (respect terms: https://www.satp.org/)
   - NACTA publications (https://nacta.gov.pk/)
   - START Global Terrorism Database (registration required: https://www.start.umd.edu/gtd/)
2. Export/extract to CSV with the required columns listed above.
3. Save as `data/raw/kpk_incidents.csv` — this automatically takes priority over the demo file.
4. Set honest `verification_status` values per row (e.g. `verified`, `unverified`, `media_report`).
5. Record here: source name, URL, retrieval date, coverage period, known limitations.
